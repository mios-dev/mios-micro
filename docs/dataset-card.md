# Dataset Card: mios-micro-sft

Supervised fine-tuning corpus for the MiOS-Micro resident model. It is generated by
`python3 -m src.mios_micro.dataset` and shipped as the `application/vnd.cncf.model.dataset.v1.raw`
layer of the mios-micro ModelPack artifact (`data/mios-micro-sft.jsonl` in the Kitfile).

The sections below follow *Datasheets for Datasets* (Gebru et al., 2021).

## Motivation

The corpus exists to teach a 1.5B model four narrow, latency-sensitive jobs that MiOS
background services need without calling a larger lane: shell command synthesis for an
immutable bootc/Fedora host, journal log triage into structured JSON, intent routing to
MiOS verbs, and OpenAI-format function calling. It is created and maintained by the MiOS
project.

## Composition

Each record is one JSON object per line with a single `messages` array in the OpenAI chat
format (`system`, `user`, `assistant`; tool-calling records carry `assistant.tool_calls`).
Records are split across four pillars in a fixed ratio: CLI synthesis 35%, log triage 25%,
intent routing 25%, function calling 15%. All instances are synthetic and are expanded from
the hand-written seed lists in `src/mios_micro/dataset.py`, so the corpus repeats those seeds
to reach the requested `--count`. It contains no personal data, no real user logs and no
third-party text.

## Collection Process

No data is collected from people or from live systems. The generator assembles records
from in-repository seeds at build time; the packaging workflow runs it with `--count 50`.
The seeds were written by the MiOS maintainers against the MiOS verb catalog and common
systemd, podman and bootc journal messages.

## Preprocessing/cleaning/labeling

Labels are the seed answers themselves: the exact command, the triage JSON object, the
routed verb, or the tool call. There is no further cleaning, deduplication or filtering;
records are shuffled after assembly. The raw seeds remain in `src/mios_micro/dataset.py`.

## Uses

Intended for LoRA/SFT of `Qwen/Qwen2.5-Coder-1.5B-Instruct` into the MiOS-Micro model and
for smoke-testing the training pipeline (`python3 -m src.mios_micro.train --dry-run`). It is
not a benchmark: the evaluation suite must not be drawn from the same seeds. It is not
suitable for general-purpose chat or for systems other than MiOS, because commands and verb
names are MiOS-specific.

## Distribution

Distributed under Apache-2.0 inside the mios-micro ModelPack OCI artifact on
`ghcr.io/mios-dev/mios-micro`, attached as a referrer of the runtime image digest and signed
with cosign. It is not published as a separate Hugging Face Hub dataset.

## Maintenance

Maintained in the `mios-dev/mios-micro` repository. Changes land as edits to the seed lists
or the pillar ratios in `src/mios_micro/dataset.py`; each packaging run regenerates the
corpus, and the layer digest in the ModelPack manifest identifies the exact copy shipped.
